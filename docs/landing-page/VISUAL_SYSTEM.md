# PART II — Visual Design System

---

# 16. Visual Identity

The Analytica landing page should communicate professionalism, intelligence, structure, and confidence.

The visual language should feel premium without becoming flashy.

The experience should resemble modern enterprise software rather than an online course platform.

The interface should feel:

• Clean

• Spacious

• Intentional

• Intelligent

• Technical

• Approachable

Every visual decision should reinforce trust.

Avoid visual noise.

Avoid unnecessary decoration.

Avoid trendy effects that reduce readability.

---

# 17. Color System

The interface should primarily use white space and typography to create hierarchy.

Color exists to guide attention—not decorate the interface.

## Primary Brand Color

Deep Navy

Purpose

• Primary headings

• Navigation

• Icons

• Major illustrations

Example

#0B1F3A

---

## Secondary Brand Blue

Purpose

• Accent gradients

• Interactive states

• Charts

• Data visualisation

• Highlights

Example

#2563EB

---

## Success Accent

Purpose

Used sparingly.

Only for:

• Active states

• Progress

• Success indicators

• AI status

• Current navigation item

• Current roadmap step

Example

#22C55E

Green should never dominate the interface.

Its purpose is to communicate progress.

---

## Neutral Scale

Use a complete neutral scale for:

Backgrounds

Borders

Muted text

Disabled components

Cards

Section separation

Prefer cool gray neutrals over warm grays.

---

## Color Distribution

Approximately:

75%

White / Light Surfaces

20%

Deep Navy

5%

Accent Colors

Color should feel earned.

Not constant.

---

# 18. Typography System

Typography is the primary visual element of the landing page.

Visitors should remember the words before they remember illustrations.

---

## Font Personality

Modern

Confident

Elegant

Readable

Professional

---

## Typography Hierarchy

Display Heading

Used only in Hero.

Very large.

Bold.

Tight line height.

Maximum visual impact.

---

Section Heading

Clear.

Confident.

High contrast.

Large whitespace above and below.

---

Body Text

Readable.

Comfortable.

Never exceed ideal reading width.

Focus on clarity.

---

Captions

Muted.

Minimal.

Used only where necessary.

---

# Hero Typography

The Hero should use the Split Tone Heading style.

Structure:

Strong statement

↓

Supporting statement (muted)

↓

Strong conclusion

Example

Learn

with real projects,

become industry ready.

Only the supporting statement should use reduced emphasis.

# 19. Spacing System

Whitespace is an intentional design element.

The page should breathe.

Never compress sections together.

Suggested spacing scale

8

16

24

32

48

64

96

128

160

Major sections should typically be separated by 128–160px.

---

# 20. Grid System

Desktop

12-column layout

Maximum width

1280px

Content width

720–900px for text-heavy sections

Cards should align consistently.

Avoid arbitrary widths.

---

# 21. Border Radius

Use soft geometry.

Cards

20–24px

Buttons

14–16px

Inputs

14px

Badges

999px

Avoid sharp edges.

---

# 22. Shadows

Shadows should communicate elevation.

Never decoration.

Use soft shadows.

Large blur.

Low opacity.

Cards should appear to float subtly.

Avoid dramatic drop shadows.

---

# 23. Borders

Prefer subtle borders over heavy shadows.

Border color should usually be:

Gray 200

or

Low-opacity navy.

Cards should feel defined without appearing boxed.

---

# 24. Glass Effects

Glassmorphism should not be a primary design language.

Small amounts are acceptable for:

Navigation

Floating cards

Badges

Tooltips

Never use full-screen glass panels.

---

# 25. Icons

Icons should be:

Simple

Outline-first

Consistent stroke width

Minimal detail

Use icons only where they improve comprehension.

---

# 26. Cards

Cards represent knowledge.

They should feel like organized pieces of information.

Every card should have:

Large padding

Clear hierarchy

Soft border

Subtle shadow

Rounded corners

Cards should never feel crowded.

---

# 27. Charts

Charts should not exist purely as decoration.

Every chart should communicate progress.

Possible chart styles

Bar Charts

Radar Charts

Progress Rings

Timeline Charts

Learning Progress

Skill Distribution

Charts should animate from zero when entering the viewport.

---

# 28. Illustrations

Illustrations should communicate product capability.

Avoid generic stock illustrations.

Preferred visuals include:

Dashboard previews

Analytics graphs

Dataset previews

AI mentor conversations

Skill radar

Progress roadmap

Project workspace

Everything shown should resemble the actual application.

---

# 29. Imagery

Photography should be avoided.

The product itself is the hero.

If imagery is used, it should support—not replace—the interface.

---

# 30. Section Rhythm

Every section should follow this rhythm.

Question

↓

Explanation

↓

Visual Proof

↓

Call to Continue

This creates a natural learning flow.

The visitor should never feel overwhelmed.

---

# 31. Design Consistency Rules

Every section must answer:

What is being taught?

Why does it matter?

What visual proves it?

What interaction reinforces it?

Every component should feel like it belongs to the same product.

No section should introduce an entirely different visual style.

Consistency is more important than novelty.
